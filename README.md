## 1. Executive Summary

Iterative numerical CFD solvers (e.g., Finite Volume Method) provide accurate physical solutions but introduce severe computational bottlenecks that prevent real-time feedback in Model Predictive Control (MPC) and interactive design loops. 

This project bridges high-fidelity fluid mechanics with real-time inference by deploying a **Fourier Neural Operator (FNO-2D)** surrogate model. Built using **PyTorch** and deployed via a lightweight **FastAPI** backend, the surrogate maps parametric boundary conditions directly to steady-state velocity ($V_x, V_y$) and temperature ($T$) fields.

```text
+--------------------------+     +----------------------------+     +-------------------------------+
|   Parametric CFD Solver  | --> |  PyTorch FNO-2D Pipeline   | --> | FastAPI CPU Cloud Microservice|
| (Pure Vectorized Python) |     |  (L2 Spatial Loss & Modes) |     | (Real-Time Inference UI) |
+--------------------------+     +----------------------------+     +-------------------------------+
```

## 2. Mathematical & Physical Architecture

The ground-truth physical dataset is generated by a custom 2D transient CFD solver resolving coupled momentum and thermal transport inside a $3.2\text{m} \times 3.2\text{m}$ domain discretized on a $64 \times 64$ grid ($\Delta x = \Delta y = 0.05\text{m}$). The domain includes a high-wall inlet, low-wall exhaust, and a constant $37^\circ\text{C}$ ($310.15\text{ K}$) heat source representing an obstacle/occupant.

### Governing Equations
The fluid motion is governed by the incompressible Navier-Stokes equations coupled with heat transport using the **Boussinesq approximation** for natural convection:

**Momentum Equations:**

$$\frac{\partial \mathbf{u}}{\partial t} + (\mathbf{u} \cdot \nabla) \mathbf{u} = -\frac{1}{\rho}\nabla p + \nu \nabla^2 \mathbf{u} + \mathbf{g}\beta(T - T_{ref})$$

**Energy Equation:**

$$\frac{\partial T}{\partial t} + \mathbf{u} \cdot \nabla T = \alpha \nabla^2 T$$

**Continuity (Incompressibility Constraint):**

$$\nabla \cdot \mathbf{u} = 0$$

### Numerical Implementation (CFD Engine)
- **Time Integration & Advection:** Explicit forward-Euler integration using 1st-order Upwind differencing for advective terms and 2nd-order Central Differencing for diffusive terms.
- **Pressure-Velocity Coupling:** Modified Chorin's Projection Method with Rhie-Chow interpolation to prevent grid checkerboarding.
- **Stability Control:** Adaptive time-stepping enforcing Courant-Friedrichs-Lewy ($\text{CFL} \le 0.45$) and Fourier diffusion limits.

## 3. Scientific Machine Learning (SciML) Pipeline

### Parametric Data Generation
Using **Latin Hypercube Sampling (LHS)**, 500 unique boundary condition pairs were generated across the physical operating domain:
- **Inlet Velocity ($V_{in}$):** $0.5 \text{ m/s} \le V_{in} \le 3.0 \text{ m/s}$
- **Inlet Temperature ($T_{in}$):** $288.15 \text{ K} \le T_{in} \le 303.15 \text{ K}$

### FNO Architecture & Training (PyTorch)
- **Spectral Modes:** $16 \times 16$ Fourier modes to capture turbulent eddies and steep thermal gradients.
- **Hidden Channels:** Expanded to 64 channels to model complex non-linear momentum-thermal cross-coupling.
- **Loss Optimization:** Integrated relative $L^2$ norm loss (`LpLoss(d=2, p=2)`) to preserve continuous physical field structures rather than point-wise MSE errors.
- **HPC VRAM Safety:** Implemented zero-leakage model serialization, exporting trained weights into C-contiguous arrays (`.npz` and `.pth`) for CPU inference.

## 4. Software Architecture & Cloud Microservice

The microservice backend (`app.py`) is engineered for production-grade reliability:

1. **Zero Cold-Start:** Model weights are loaded into RAM during application lifespan boot, ensuring $0\text{ms}$ startup lag on incoming requests.
2. **Inference Acceleration:** Uses `@torch.inference_mode()` and vectorized tensor operations to eliminate autograd overhead.
3. **Cross-Origin Security:** Fully configured CORS middleware supporting asynchronous communication with the interactive frontend.

```text
       [ Client / Browser UI ]
                  |
    (POST /predict - Velocity & Temp)
                  |
                  v
       [ FastAPI Microservice ]  <--- Pre-loaded PyTorch Model in RAM
                  |
    (Inference Output: 3x64x64 Array)
                  |
                  v
       [ Real-time Field Render ]
```
